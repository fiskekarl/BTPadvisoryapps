# BTP Architecture Compliance Scorecard

App **#3** in the BTP Advisory Apps arsenal — your IP centerpiece. Codifies your opinionated governance baseline into an executable rule engine that scores the client's BTP landscape A/B/C/D/F.

## Rule engine

- Rules live in `db/seed/rules.json` and are seeded into the `Rule` table on first boot.
- Each rule has a `kind` that maps to an evaluator in `srv/rules/registry.js`.
- ScoreAdmin role can edit rules in-app — the tuned ruleset stays with the client's leave-behind copy.

### Built-in evaluators (v1)

| Kind | Logic |
|---|---|
| `label-required` | A label (e.g. `costCenter`) must be present on subaccounts in scope |
| `destination-auth-forbidden` | No destination in the scoped subaccounts uses any auth method in `forbidden[]` |
| `max-days-inactive` | No subaccount inactive more than `maxDays` |
| `name-pattern` | `displayName` matches a regex (tier naming convention) |
| `mfa-for-admin-rcs` | TODO — needs IAS API binding |

### Adding a new evaluator

1. Add `kind: 'my-new-check'` to a rule in `db/seed/rules.json`.
2. Add an evaluator function to `evaluators` in `srv/rules/registry.js`.
3. Restart — the rule is picked up on next scan.

## Snapshots

`POST /odata/v4/score/runScan` persists a `ScoreSnapshot` for "before vs after" workshop deliverables. Snapshots are immutable and exportable; the engagement deck is generated by reading two snapshots and producing a side-by-side slide.

## Data wiring

The scorecard reads inventory data from sister apps #1 and #2 (or mock data when env vars are unset):

```bash
LIFECYCLE_ODATA_URL=https://lifecycle-srv.cfapps.<region>/odata/v4/lifecycle
DESTINV_ODATA_URL=https://destinv-srv.cfapps.<region>/odata/v4/destinv
IAS_API_URL=https://<tenant>.accounts.ondemand.com
```
